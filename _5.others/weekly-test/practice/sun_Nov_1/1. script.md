Let me restate the problem: given an array of integers nums and an integer
target, return the indices of the two numbers that add up to target.
We assume exactly one solution exists, and we can't reuse the same element.

The brute-force approach checks every pair, which is O(n squared) time.
We can do better.

I'll use a hash map. The idea: for each number x, the complement we need
is target minus x. If we've already seen the complement, we have our answer.
We check the map before storing the current number, so we never reuse
the same element.

Walking through the code: I create an empty dictionary called seen.
I iterate with index i and value x using enumerate.
For each x, I compute need = target minus x.
If need is in seen, I return seen[need] and i.
Otherwise I store seen[x] = i and move on.

For example, with nums = [2, 7, 11, 15] and target = 9:
at x = 2, need = 7, not in the map, so store it.
At x = 7, need = 2, which is in the map — return indices 0 and 1.

Time complexity is O(n): one pass with O(1) dictionary lookups.
Space complexity is O(n) for the hash map in the worst case.
